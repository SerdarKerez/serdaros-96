# SerdarOS 96 — bilingual (TR / EN) contract

Rules
- **TR mode must stay exactly as it is today** (current strings, including English OS chrome like "Start",
  "My Computer", "Gallery", "Contact Me", "Blog"). **EN mode: every user-visible string is English** —
  UI, toasts, aria-labels, titles, alt text, captions, content, blog posts, project pages, and text inside SVG images.
- Language API (main session, read-only): `lib/i18n.tsx` → `LangProvider` (already wraps the app in
  `components/SerdarOS.tsx`), `useLang()` → `{ lang, setLang, toggle, t(tr, en) }`, types `Lang`, `L<T>`, `pick()`.
  Preference persisted in storage key `lang`; `<html lang>` is updated automatically.
- Data APIs (main session, read-only):
  - `getContent(lang)` from `lib/content-i18n.ts` → TR `lib/content.ts` (`CONTENT`) / EN `lib/content.en.ts` (`CONTENT_EN`, same `Content` type).
  - `getPosts(lang)`, `findPost(lang, slug)`, `formatDate(iso, lang)`, `readingMinutes(post)` from `lib/blog`.
  - `projectDetails(lang, slug)` from `lib/projects`.
- Slugs, ids, storage keys, file names of TR assets: unchanged. EN SVG variants live next to the TR ones as
  `<name>.en.svg` (e.g. `/blog/raw-dna-mapping/cover.en.svg`) and EN data files reference those.
- Natural, fluent English (not word-for-word). Keep technical accuracy; keep code blocks identical except
  translating comments/output labels where they are Turkish prose.

Ownership
| files | owner |
|---|---|
| lib/i18n.tsx, lib/content-i18n.ts, lib/blog/index.ts, lib/projects/index.ts, components/SerdarOS.tsx | main session |
| lib/content.en.ts, lib/projects/*.en.ts, public/projects/**/*.en.svg | translator-content |
| lib/blog/*.en.ts, public/blog/**/*.en.svg | translator-blog |
| everything in components/** (except SerdarOS.tsx), styles/** | ui-i18n |
